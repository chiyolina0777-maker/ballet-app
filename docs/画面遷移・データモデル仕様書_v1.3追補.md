## 1. 全体方針 ＜追記＞

v1.2 の方針に、以下2項を追加する。

- **会員限定情報の非公開原則。** 会員組織限定で告知された情報のうち、キャスト・申込URL・
  シリアルコード・会員特典の詳細は、いかなる出力面にも出さない。
  公開してよいのは「その先行が存在し、いつからいつまでか」という事実に限る。
  この原則は本サービスの信用基盤であり、B2B提携の前提でもある。違反は最も重大な事故として扱う。
- **出所の記録。** キャスト・発売段階の各レコードは、情報の出所（公開ページ / 会員サイト /
  会員メール / プレス / 手入力）を必ず記録する。後から「これは公開情報だったか」を
  検証できる状態を保つ。

## 2. キャストの公開状態 ＜新設＞

### 2.1 状態の定義

`casts.status` は次の4値をとる。

| 値 | 意味 | 出力可否 |
| --- | --- | --- |
| `tbd` | 未発表。誰も知らない | 不可 |
| `member_only` | 会員限定で発表済み。一般には未公開 | **不可** |
| `announced` | 一般公開済み | 可 |
| `final` | 当日確定（変更なしが確定した状態） | 可 |

`tbd` と `member_only` を区別することが本節の要点である。
v1.2 の `is_published`（boolean）では両者が同じ「false」に潰れており、
運用上「まだ出ていない」のか「出せない」のかが判別できなかった。

### 2.2 出力面のゲート

`is_published` は `status` から自動導出される派生値であり、直接更新しない。

```
is_published = status ∈ {announced, final}
               AND (publish_not_before IS NULL OR publish_not_before <= now())
```

`is_published = false` のキャストは、以下の**すべての面**で出力しない。

- LINE通知の本文
- 公演詳細画面のキャスト表
- 日別キャスト一覧
- ダンサー詳細画面の出演予定
- 検索インデックス（全文検索・OGP・構造化データを含む）
- 公開API / RSS 等の外部出力

通知だけをフィルタする実装は不可。画面から漏れる。

### 2.3 解禁の運用

`publish_not_before` に解禁予定日時を入れておくと、時刻経過後に公開される。
ただし自動では反映されないため、通知ワーカーと同一周期で
`release_scheduled_casts()` を呼ぶこと。

解禁日時が不明な場合は `publish_not_before` を NULL のままにし、
公開を確認した時点で手動で `status` を `announced` に変更する。

### 2.4 監視

管理画面ダッシュボードに `qa_leaked_member_only_casts` の件数を常時表示する。
**常に0件**であること。1件でも出た場合は即座に調査する。

解禁待ちの一覧は `pending_cast_releases` で確認できる。手動運用の作業キューとして使う。

### 2.5 基準日と変更

各団体はキャスト情報に基準日を明記している（例：「掲載キャスト予定は2026年6月12日現在」）。
`casts.as_of` に保持し、画面にも表示する。

キャストは怪我等で変更されうる。詳細ページの内容をハッシュで比較して差分を検知し、
変更があれば「キャスト変更」として通知する。主演目当てのユーザーには価値が高い。

## 3. ツアー公演と会場 ＜差し替え：データモデル章＞

### 3.1 中間テーブルの導入

v1.2 は `performances.venue_id` により単一会場を前提としていたが、
Kバレエの Spring / Autumn Tour、NBS の地方公演では
**都市ごとに主催者・料金・発売日が異なる**。

`performance_venues`（公演 × 会場）を新設し、以下をここに持たせる。

- 会場、都市ラベル（原文の「[東京]」等）、公演期間
- 主催者（例：TBS、日本舞台芸術振興会）
- チケットURL

`shows`・`sale_stages`・`seat_types` はこの中間テーブルを参照する。

`performances.venue_id` は互換のため当面残すが、新規コードは参照しない。v1.4 で削除する。

### 3.2 sale_stages の紐づけ

`sale_stages.performance_venue_id` は nullable。

- **NULL** … 公演全体に適用（単一会場、または全会場共通の発売）
- **値あり** … その会場のみに適用

## 4. 発売段階の拡張 ＜差し替え：発売段階章＞

### 4.1 5段階モデルは維持

`s1_fastest` / `s2_member` / `s3_free` / `s4_general` / `s5_discount` の内部区分と、
ユーザー向け3カテゴリ（先行 / 一般発売 / 割引）への写像は v1.2 のまま維持する。

ただし **団体ごとに使う段階を選択する**方式に変更する。
`companies.sale_stage_names`（会社マスタのテンプレート）で定義した段階のみを
その団体の公演で選択可能とし、管理画面のドロップダウンにも定義済みの段階だけを出す。

| 団体 | s1 | s2 | s3 | s4 | s5 |
| --- | --- | --- | --- | --- | --- |
| 新国立劇場バレエ団 | 郵送申込（シード権優先） | アトレ会員先行 | 新国メンバーズ先行 | 一般発売 | **定義しない** |
| 東京バレエ団（NBS） | — | CAT会員WEB先行 | NBS WEBチケット先行 | 一般発売 | 親子割引 / U25・U39シート |
| Kバレエ トウキョウ | — | K-BALLET FRIENDS先行 | — | 一般販売 | **定義しない**（席種で表現） |

新国立で `s5` を定義しないのは、U25・39優待がメール／LINE経由の
**クローズド配布**であり、公開告知されていないため。第1節の原則により扱わない。

NBS で `s5` を定義するのは、割引枠が**日時つきで公式サイトに掲載され、
独立した発売日を持つ**ため。U25シートは 2,000円（S席 15,000円）で、
対象層にとっては一般発売より重要な販売機会になる。

Kバレエの学生券・A親子席は一般発売と同時であり、段階ではなく席種として扱う（第5節）。

### 4.2 表示順は日時と独立

NBS では割引枠が一般発売の約1.5か月**後**に開く。
「`stage_type` の番号順＝時系列」という仮定は成立しないため、
`sale_stages.sort_order` を独立に持ち、画面表示は日時昇順を基本とする。

### 4.3 抽選型への対応

`sale_type` に `first_come`（先着）/ `lottery`（抽選）を持つ。
抽選の場合、締切は1つではない。

| 項目 | 通知対象 |
| --- | --- |
| `opens_at` | 申込開始 |
| `closes_at` | **申込締切** ← 中核 |
| `result_announce_at` | 当落発表 |
| `payment_closes_at` | **入金締切** ← 失権に直結 |

`upcoming_sale_triggers` ビューがこの4種を1行ずつに展開する。

### 4.4 締切時刻が不明な場合

団体によって `closes_at` に時刻が明記されない
（例：新国立「アトレ会員先行販売期間：2026年8月1日（土）10:00〜**8月10日（月）**」）。

取込時は終日として 23:59 で保持し、通知は**前日と当日朝の2回**を送る。
画面表示では「8月10日（月）まで」と時刻を伏せ、正確な時刻は公式サイトを案内する。

### 4.5 購入窓口の制約

`channel_note` に自由記述で保持する。
例：Kバレエの A親子席・学生券は「TBSチケット・チケットぴあWEBのみ受付」。
特定席種を狙うユーザーには実用価値が高いため、通知本文にも含める。

### 4.6 プレイガイド先行の扱い

NBS ではプレイガイド4社（e+・ぴあ・ローソン・楽天）が
`s3_free` と同一期間に座席選択先行を実施する。
段階を4つに分けると冗長になるため、フェーズ1では代表1件を `s3_free` として登録し、
他社は `channel_note` に併記する。

## 5. 席種 ＜新設＞

### 5.1 位置づけ

`seat_types` は `performance_venues` に紐づく。
料金・会員価格・割引フラグ・利用条件・購入窓口制約を持つ。

### 5.2 会員割引は席種の属性

アトレ会員（先行時10% / 一般後5%）、CAT会員（10%）のような会員割引は
**販売段階ではなく価格の属性**である。`member_price` と `member_org_id` で表現する。

### 5.3 割引席種と割引段階の使い分け

| ケース | 表現 |
| --- | --- |
| 独立した発売日を持つ（NBS U25シート） | `seat_types` + `sale_stage_id` で段階に紐づけ |
| 一般発売と同時（Kバレエ学生券） | `seat_types` のみ。`is_discount = true` |
| ペア割引・親子割引など購入条件 | `eligibility` に記述 |

### 5.4 既知の制約

同一席種でも公演回によって特典内容が変わる場合がある
（Kバレエ K-BALLET SELECTION席：7/19昼・7/20は「フォトカード付」、7/19夜は「手渡し」）。
フェーズ1では `note` に文章で持つ。構造化が必要になれば v1.4 で `seat_type_shows` を追加する。

## 6. 会員組織とユーザーの加入状況 ＜新設＞

### 6.1 目的

会員先行の通知を、その会員組織に加入していないユーザーに送っても購入できない。
`user_memberships` により加入状況を保持し、通知を絞り込む。

副次的に、非会員には「この公演には ○○ 会員先行があります（入会はこちら）」を
出すことができ、**バレエ団への送客**になる。B2B提携の交渉材料として使える。

### 6.2 通知の宛先

| 段階 | 宛先 |
| --- | --- |
| `s1` / `s2` / `s3`（会員先行） | 該当 `membership_org` の加入者、かつ公演／ダンサーのフォロワー |
| 同上（非加入者） | 通知は送らず、公演詳細画面で入会導線のみ表示 |
| `s4`（一般発売） | フォロワー全員 |
| `s5`（割引） | フォロワー全員（対象年齢等は本文で明示） |

### 6.3 設定画面

設定に「加入している会員組織」のチェックリストを置く。
`membership_orgs` から団体別に一覧表示する。任意入力とし、未設定の場合は
会員先行通知も送る（漏れるより過剰なほうが害が小さいため）。

## 7. 通知仕様の更新 ＜差し替え：通知章＞

### 7.1 先行時にキャストを出せない問題

Kバレエでは、FC先行の時点でキャストが会員限定発表であることが多い。
このとき、フォロー中のダンサーが出演していても通知に含められない。

### 7.2 通知を2段階に分ける

| # | 通知 | 起点 | 内容 | 有料/無料 |
| --- | --- | --- | --- | --- |
| 1 | 先行開始・締切 | バレエ団フォロー | 公演名・会場・日程・先行期間。**キャストには触れない** | 有料 |
| 2 | キャスト発表 | ダンサーフォロー | 公開後に「フォロー中の○○が出演」 | 無料 |

Kバレエの場合、キャスト公開は一般販売の前後に来るため、
2 の通知は一般発売には十分間に合う。
先行を逃したくない層は 1 で動け、ダンサー目当ての層は 2 で動ける。
結果として通知機会はむしろ増える。

### 7.3 通知本文に会員限定情報を混ぜない

通知テンプレートは `is_published = true` のキャストのみを参照する。
テンプレート側で `status` を見ない実装にすること（`is_published` に一本化する）。

### 7.4 シード権対象公演の表示

新国立劇場では、対象公演の購入実績が翌シーズンの郵送申込シード権につながる。
`performances.counts_toward_seed_right = true` の公演は、
通知本文と公演詳細に「次シーズンのシード権対象公演です」を1行加える。

実装コストがほぼゼロで、購入判断を実際に変える情報であるため費用対効果が高い。

## 8. 画面への影響

### 8.1 公演詳細

- 会場が複数ある場合、`performance_venues` ごとにタブまたはセクションで分割
- 料金表は `seat_types` から生成。会員価格は列を分けて表示
- 発売段階は日時昇順。会員先行には入会導線を併記
- キャストは `is_published = true` のみ。未公開時は「キャスト未発表」と表示し、
  会員限定発表済みであることは**表示しない**（存在を示唆しない）
- `as_of` を「キャスト情報：○月○日現在」として脚注表示

### 8.2 ダンサー詳細

出演予定は `is_published = true` のキャストのみ。ゲスト出演者は `affiliation_text` を表示。

### 8.3 管理画面

- キャスト入力に `status` のセレクトと `publish_not_before` を追加
- `member_only` を選択した際に警告バナーを表示（「この情報は公開されません」）
- 出所（`source_type`）を必須入力とする
- ダッシュボードに `qa_leaked_member_only_casts` の件数と
  `pending_cast_releases` の一覧を表示

## 9. 団体別の取込方針

汎用パーサは成立しない。キャスト表の構造が団体ごとに全く異なるため、
**団体別パーサ**を前提とする。各団体のフォーマットは年単位で安定しており、初期コストのみで済む。

| | 新国立劇場 | 東京バレエ団（NBS） | Kバレエ |
| --- | --- | --- | --- |
| 公演一覧 | `/variety/` はJS描画 → 別経路が必要 | 静的 | 静的 |
| 公演詳細 | 静的。発売段階まで完備 | 静的。発売段階まで完備 | 静的だが**先行日程なし** |
| キャスト表 | 公演回ごとの見出し | 役 × 日付グループ | 演目 × 公演回 |
| 先行情報 | 自動取得可 | 自動取得可 | **手入力**（会員サイト） |
| 会場 | 単一 | 単一〜複数 | ツアー多数 |

### 9.1 新国立劇場

`/ballet-dance/variety/` はクライアント側描画のため一覧が取得できない。
公演詳細（`/ballet/{slug}/`）は完全に静的で、日程・キャスト・料金・発売段階がすべて揃う。
一覧の取得経路は、(a) `/variety/` の背後のデータ源、(b) `sitemap.xml`、
(c) シーズンラインアップ発表記事、のいずれかで解決する。

ニュース一覧（`/ballet-dance/news/`）は静的で年別ページもあり、
詳細URLが連番IDのため差分検知が容易。キャスト更新の検知はここを使う。

### 9.2 東京バレエ団（NBS）

`/stages/{年}/{slug}/` の4ページ構成（index / program / cast / info）。すべて静的。
キャスト表の日付グループ（「2/27, 3/1」）は**取込時に show 単位へ展開**し、
原文表記を `cast_group_label` に保持する。

トリプルビル等で1公演が複数演目を含むため、作品層（`works`）との紐づけを必ず行う。

### 9.3 Kバレエ トウキョウ

公演ページには一般販売日のみが記載され、先行は K-BALLET FRIENDS（別ドメインの会員サイト）
にある。**先行情報は管理画面から手入力する**。

年間4〜6演目 × 2〜3段階 ＝ 年15〜20件程度であり、自動化するより手入力のほうが
コスト・精度の両面で有利。抽選型の複数締切は人が読んで判断したほうが確実である。

キャストは先行時点で会員限定であることが多い。`status = member_only` で登録し、
一般公開を確認してから `announced` に変更する。

なお、公演ページの「キャスト表[PDF]」リンクが `xxx.pdf` になっている（先方のリンク切れ）。
PDF に依存した取得設計は避ける。

### 9.4 ダンサーの名寄せ

団体ごとに個別ページの slug 規則が異なる。

- 新国立：`/dancer/list/okumura_kosuke.html`（姓_名・小文字）
- Kバレエ：`/dancers/Masaya_Yamamoto.html`（名_姓・先頭大文字）

`(source_domain, external_slug)` を安定キーとする。
リンクのないキャスト（新規入団者等）は名前によるフォールバック照合を行う。

ゲスト出演者（例：オニール八菜／パリ・オペラ座バレエ エトワール）は
`is_guest = true` とし、所属を `affiliation_text` に文字列で保持する。

## 10. 運用ルール

1. CSVインポートは常に下書き取込。通知とは分離する（v1.1 から継続）
2. 手入力の先行情報は、出所（`source_type`）を必ず記録する
3. 会員サイト・会員メール由来のキャストは `status = member_only` で登録し、
   一般公開を**目視で確認**してから `announced` に変更する
4. 「保存して通知」の前に通知プレビュー（ダンサー別受信者数・重複除外済み）と
   二段確認を経る（v1.2 から継続）
5. `qa_leaked_member_only_casts` が1件以上になった場合、通知送信を停止して調査する

## 11. v1.4 以降に送るもの

- `performances.venue_id` の削除（`performance_venues` への完全移行後）
- `seat_type_shows`（公演回ごとに特典が変わる席種の構造化）
- シード権の獲得条件トラッキング（「あと何公演」表示）。購入履歴の入力が必要になるため対象外
- シーズンセット券（`season_packages`）。バレエでは新国立に存在せず（オペラのみ）、
  他団体で必要になった時点で検討する
- Kバレエ以外の団体（牧阿佐美バレヱ団、スターダンサーズ、松山バレエ団等）への拡大。
  会員先行の手入力は属人性があるため、B2B提携の提案項目として
  「先行情報の提供」を含めることで解消を図る
